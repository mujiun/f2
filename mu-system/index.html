Typography

System font stack (SF Pro on Apple devices). Tight letter-spacing on headings.

<p class="body">Body text</p>
<p class="body-2">Secondary text</p>

<div class="eyebrow">Eyebrow label</div>
  • The classes are visual only — pair them with semantic tags: <h1>–<h4> for headings, <p> for body text.
  • One h1 per page, and don't skip heading levels — screen-reader users navigate by heading outline.
  • caption and eyebrow render small and grey — keep them for metadata, never for essential instructions (contrast is lower).

Buttons

Primary is dark grey. Three variants × three sizes, plus pill and icon shapes.

btnbtn-primarybtn-secondarybtn-ghostbtn-smbtn-lgbtn-pillbtn-iconbtn-block
<button class="btn btn-primary">Primary</button>
<button class="btn btn-secondary">Secondary</button>
<button class="btn btn-ghost">Ghost</button>
<button class="btn btn-primary" disabled>Disabled</button>
  • Use a real <button> for actions and an <a href> for navigation — never a styled <div>.
  • disabled removes the button from the tab order; if users should still discover it, use aria-disabled="true" and block the click in JS instead.
  • Don't remove the focus outline — keyboard users need a visible :focus-visible ring.
<button class="btn btn-primary btn-sm">Small</button>
<button class="btn btn-primary btn-lg">Large</button>
<button class="btn btn-primary btn-pill">Pill</button>
<!-- icon-only buttons need aria-label -->
<button class="btn btn-secondary btn-icon" aria-label="Add">…svg…</button>
  • Icon-only buttons have no text, so they need an aria-label naming the action (e.g. "Add").
  • Mark the icon itself decorative with aria-hidden="true" on the <svg>.
  • Keep touch targets comfortable — btn-sm is fine in dense UI, but aim for ~44px hit areas on primary mobile actions.

Inputs & Forms

Text input, textarea, select, switch and checkbox. Focus = dark border + soft ring. Wrap control + text in a <label> so every field has an accessible name.

fieldlabelinputhintswitchcheckboxcontrol-row
<label class="field">
  <span class="label">Email</span>
  <input class="input" type="email" placeholder="you@example.com">
  <span class="hint">We'll never share your email.</span>
</label>

<label class="control-row">
  <input type="checkbox" class="switch" role="switch" checked> Enable notifications
</label>

<label class="control-row">
  <input type="checkbox" class="checkbox" checked> I agree to the terms
</label>
  • Every control needs an accessible name — wrapping control + text in one <label> (as here) or linking them with for/id.
  • Placeholder text is not a label — it disappears on input and has low contrast.
  • Hint text outside the label should be linked with aria-describedby; the same goes for error messages.
  • The switch uses role="switch" so screen readers announce on/off instead of checked/unchecked.

Badges & Chips

Badges for status, chips for filters (click to toggle — aria-pressed tracks state).

badgebadge-solidbadge-softbadge-outlinebadge-dotchip
New Draft Archived Live 
<span class="badge badge-solid">New</span>
<span class="badge badge-soft">Draft</span>
<span class="badge badge-outline">Archived</span>
<span class="badge badge-soft"><span class="badge-dot"></span> Live</span>
  • Never rely on the dot or shade alone to convey status — the text label ("Live", "Draft") carries the meaning.
  • Badges are plain text spans, so they're read inline with surrounding content; no extra roles needed.
  • If a badge announces something time-sensitive (e.g. an error count that updates), put it in an aria-live="polite" region.
<button class="chip is-active" aria-pressed="true">All</button>
<button class="chip" aria-pressed="false">Design</button>
<button class="chip" aria-pressed="false">Prototype</button>
  • Filter chips are real <button>s with aria-pressed — keep the attribute in sync when toggling .is-active.
  • Wrap a chip set in a container with role="group" and an aria-label (e.g. "Filter projects") so the set is announced together.
  • When a filter changes visible results, announce the outcome (e.g. "8 results") in an aria-live region.

  • If the avatar sits next to the person's visible name, use alt="" so the name isn't read twice.

    <div class="card-title">Raised card</div>

<!-- image-only, boxed -->
<div class="card card-img card-raised card-hover">
  <img src="…" alt="describe the image">
</div>

<!-- image-only, flat (floating rounded image) -->
<div class="card card-flat card-img card-hover">
  <div class="card-media"><img src="…" alt="describe the image"></div>
</div>
  • In an image-only card the image is the entire content — a meaningful alt is mandatory, or the card is invisible to screen readers.
  • If the card links somewhere, the alt should describe the destination ("Case study: bulk reply flow"), not the picture's pixels.
  • Any text baked into the image must also exist as real text or in the alt.

Media

The signature treatment: image floats on a grey surface with a soft shadow. Use media-flush for edge-to-edge.

mediamedia-deepmedia-flushmedia-caption
Default — floating image with shadow on grey surface
<div class="media">
  <img src="…" alt="describe the image">
</div>
<div class="media-caption">Caption text</div>
  • For a captioned image prefer <figure> + <figcaption class="media-caption"> so the caption is programmatically tied to the image.
  • The caption doesn't replace alt — alt describes the image, the caption comments on it.
  • For video in a media frame, provide captions/transcripts and avoid autoplay with sound.
<div class="media media-flush">
  <img src="…" alt="describe the image">
</div>
  • Flush media is often decorative scenery — if it adds no information, use alt="" so screen readers skip it.
  • Don't put essential content (text, charts) in a purely decorative flush image.

Tabs

Segmented control and underline variant, with tab roles and aria-selected.

tabstabtabs-line
<div class="tabs" role="tablist">
  <button class="tab is-active" role="tab" aria-selected="true">Overview</button>
  <button class="tab" role="tab" aria-selected="false">Analytics</button>
</div>

<script>
document.querySelectorAll('.tabs').forEach(g =>
  g.addEventListener('click', e => {
    const t = e.target.closest('.tab'); if (!t) return;
    g.querySelectorAll('.tab').forEach(x => {
      x.classList.remove('is-active'); x.setAttribute('aria-selected', 'false');
    });
    t.classList.add('is-active'); t.setAttribute('aria-selected', 'true');
  }));
</script>
  • Pair role="tablist"/role="tab" with panels: each tab gets aria-controls pointing to a role="tabpanel" labelled by the tab.
  • Implement roving tabindex — active tab tabindex="0", others -1 — and move selection with ←/→ arrow keys.
  • If the control only filters a list (not real panels), drop the tab roles and use buttons with aria-pressed instead.

Dropdown

Menu opens below the trigger. Toggle .is-open, sync aria-expanded. Escape and outside-click close it.

dropdownmenumenu-rightmenu-itemmenu-dividermenu-label
Actions
<div class="dropdown">
  <button class="btn btn-secondary" aria-haspopup="menu" aria-expanded="false"
          onclick="const d=this.parentElement; d.classList.toggle('is-open');
                   this.setAttribute('aria-expanded', d.classList.contains('is-open'));">
    Options
  </button>
  <div class="menu" role="menu">
    <div class="menu-label">Actions</div>
    <button class="menu-item" role="menuitem">Duplicate</button>
    <button class="menu-item" role="menuitem">Rename</button>
    <div class="menu-divider"></div>
    <button class="menu-item" role="menuitem">Delete</button>
  </div>
</div>
  • Keep aria-expanded on the trigger in sync with .is-open, and set aria-haspopup="menu".
  • Escape and outside-click close the menu (built in here) — also return focus to the trigger when it closes.
  • For the full menu pattern, ↑/↓ should move between items; menu items are real <button>s so Enter/Space work for free.

Modal

Overlay + centered dialog. Closes on overlay click, Cancel, and Escape.

modal-overlaymodalmodal-lgmodal-titlemodal-descmodal-actions
<button class="btn btn-primary"
        onclick="document.getElementById('m1').classList.add('is-open')">Open</button>

<div class="modal-overlay" id="m1"
     onclick="if(event.target===this)this.classList.remove('is-open')">
  <div class="modal" role="dialog" aria-modal="true" aria-labelledby="m1-title">
    <div class="modal-title" id="m1-title">Delete project?</div>
    <div class="modal-desc">This action can't be undone.</div>
    <div class="modal-actions">
      <button class="btn btn-secondary"
              onclick="document.getElementById('m1').classList.remove('is-open')">Cancel</button>
      <button class="btn btn-primary">Delete</button>
    </div>
  </div>
</div>
  • role="dialog" + aria-modal="true" + aria-labelledby pointing at the title (as here) is the minimum.
  • On open, move focus to the dialog (or its first control); on close, return focus to the element that opened it.
  • Trap Tab inside the dialog while open — or use the native <dialog> element, which handles focus and Escape for you.
